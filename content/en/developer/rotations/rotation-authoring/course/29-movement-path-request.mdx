# 29. Request and validate a path

`RequestPath` is asynchronous. Accept only a complete, non-empty result before
installing movement:

```lua
local function UsablePath(result)
    return type(result) == "table"
        and result.ok == true
        and result.isComplete ~= false
        and type(result.path) == "table"
        and #result.path > 0
end

NX.Movement.RequestPath(x, y, z, function(result)
    if not UsablePath(result) then
        -- Try another candidate or release ownership.
        return
    end
end)
```

The callback may run inline for cached results or invalid input, so store request
state before calling. `RequestPath` returns a numeric request ID (`0` if setup
fails); the result's `requestId` identifies its callback and its `status` is a
numeric router status, rather than a pollable `pending` state. A partial path
ends at a mesh edge; it is not proof that the destination was reached.

The [complete example](./32-movement-fallback) defines the candidate coordinates
and consumes callback results from an inbox in a live pulse. It does not recurse
into another request from a callback.
