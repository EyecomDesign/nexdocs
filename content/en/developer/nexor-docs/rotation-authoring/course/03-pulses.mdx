# 3. Pulses and the first load

The engine maps live states to pulse names. A rotation must provide
`EngagementPulse`, `CombatPulse`, and `OutOfCombatPulse`. `MultiPullPulse` is
optional; when it is absent, the engine falls back to `CombatPulse`.

| State | Pulse | Meaning |
| --- | --- | --- |
| Engage | `EngagementPulse` | Open the first action window. |
| Pulling or killing | `CombatPulse` | Run the normal priority ladder. |
| Moving, waiting, searching, or map movement | `OutOfCombatPulse` | Drain buffs, pet work, and other OOC tasks. |
| MultiPull | `MultiPullPulse` | Apply an explicit gather policy when the rotation has one. |

## The out-of-combat drain contract

`OutOfCombatPulse` returns `true` while it still has work. It returns `false` when
the pulse is done. The engine uses that result to decide whether to keep asking
for out-of-combat work. Returning `nil` or `true` forever can strand the state.

The first loadable checkpoint is intentionally boring:

```lua
local Rotation = {
    OutOfCombatPulse = function()
        if NX.Pet.Maintain() then
            return true
        end
        return false
    end,

    EngagementPulse = function()
        return false
    end,

    CombatPulse = function()
        return false
    end,
}

return Rotation
```
