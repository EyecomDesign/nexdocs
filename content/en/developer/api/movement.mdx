# Movement

Use `NX.Movement` for movement policy that genuinely belongs to a rotation. The
framework owns navigation, waypoint progress, directional key holds, and facing.
Do not use the private `NEX` namespace or raw directional bindings from a rotation.

## Public methods

| Method | Purpose |
| --- | --- |
| `MoveTo(x, y, z, mapId)` | Pathfind to a coordinate using ordinary forward movement. |
| `MoveBackwardTo(x, y, z, mapId)` | Pathfind while holding backward and facing away from travel. |
| `MoveStrafeTo(x, y, z, mapId)` | Pathfind while using the left strafe binding. |
| `RequestPath(x, y, z, callback, opts)` | Request a path asynchronously without starting movement. |
| `FollowPath(path, style, mapId)` | Install a supplied same-map path and begin following it. |
| `SetRotationMovementOverride(enabled)` | Claim or release a short route while combat is active. |
| `StopMovement()` | Cancel the active route and movement keys. |
| `FaceToPosition(x, y, z, immediate)` | Hand facing back to a position, smoothly by default. |
| `ResumeNavigation()` | Resume framework-owned navigation after a rotation-owned route. |

`MoveTo`, `MoveBackwardTo`, and `MoveStrafeTo` are destination helpers. Call them
when the destination changes, not on every pulse. Calling `StopMovement()` every
tick cancels navigation and can keep the character stationary.

## RequestPath and FollowPath

`RequestPath(x, y, z, callback, opts)` returns a numeric request ID, or `0` when
the request cannot be set up. Its result comes through `callback(result)`.
Prepare callback state before calling: cache hits and invalid input can call
back inline. The router normally resolves once; author logic must still guard
late results after its own timeout or cancellation.

| Field | Meaning |
| --- | --- |
| `ok` | The router returned a usable result. |
| `path` | Ordered `{x, y, z}` points, or `nil` on failure. |
| `isComplete` | `false` means the route is partial and did not reach the goal. |
| `mapId` | Map on which the route was generated. |
| `reason` | Failure or result explanation for diagnostics. |
| `source` | Router source, such as cache, HTTP, or unlocker fallback. |
| `status` | Numeric router PathStatus value; it is not a pollable request state. |
| `requestId` | ID of the request that produced this result. |
| `attempts` | Router attempts used for this result. |

Accept a route only when `result.ok == true`, `result.isComplete ~= false`, and
`result.path` is a non-empty table. A partial path is not a successful retreat;
it ends at a mesh edge and must be rejected or handled by an explicit policy.

Use `ok` and `isComplete` for acceptance and retain `status`, `reason`, `source`
and `attempts` for diagnostics. Failure can arrive immediately (for example
`invalid_input` or `player_unavailable`) or after router work. The
[complete bounded example](../rotations/rotation-authoring/course/32-movement-fallback)
checks the request ID and target identity as well as the result shape.

`FollowPath` copies and validates the supplied points. Invalid input returns
`false, reason` and leaves the active route unchanged. A valid route cancels the
previous navigation request and follows the supplied points without asking the
router for a replacement.

## Movement styles

| Style | Facing and directional binding |
| --- | --- |
| `forward` | Normal forward movement; the default. |
| `backward` | Backward binding; facing opposite the travel direction. |
| `strafe` | Left strafe; facing perpendicular to travel. |
| `strafe-inward` | Left strafe with a 20-degree inward facing bias. |
| `strafe-right` | Right strafe; facing perpendicular to travel. |
| `strafe-inward-right` | Right strafe with a 20-degree inward facing bias. |

The inward styles keep a nearby threat closer to the forward-facing cone while
the character continues to drift away. They do not turn the camera or track a mob
automatically.

## Owning a short route during combat

Combat may normally finish approach and clear navigation while a target is in
range. A rotation-owned retreat claims with
`SetRotationMovementOverride(true)` before requesting and releases with
`StopMovement()`, `SetRotationMovementOverride(false)` and `ResumeNavigation()`
on every exit. The override is global movement ownership, not an owner token.

Keep the normal combat priority running while the route is pending or active. A
movement helper should not turn an asynchronous path request into a pulse-wide
early return. Use a generation counter and target identity check before installing
a late callback result. For a point that may be unwalkable, try a bounded list of
nearby radial candidates sequentially. The
[bounded movement fallback lesson](../rotations/rotation-authoring/course/32-movement-fallback)
renders the single authoritative
[downloadable example](/rotation-authoring/Bounded_Movement_Example.lua),
including cancellation, request/route/total deadlines, target loss, a pulse-loss
lease for pause and endpoint arrival checks. Its real Warlock priority keeps
running while movement waits.

The current public API has no standalone `CancelRequest`, rotation pause getter
or route-completed event. `StopMovement()` clears the movement machine's route
and its own pending request; it does not cancel a separately issued
`RequestPath`. The example invalidates that callback and keeps its in-flight
slot occupied until it settles, so retries cannot overlap. A timed-out request
that never settles requires ending/reloading the demo rather than creating an
unbounded queue. No future path-distance API is needed.

Before switching or unloading this demo rotation, turn its `Retreat` toggle off
and wait for the cleanup diagnostic (or a completed maneuver). A short pulse-loss
watchdog handles pauses conservatively, but cannot identify a new rotation's
route. Do not carry its timer across an arbitrary replacement: the present API
does not provide script disposal or isolated route ownership.

`FaceToPosition(..., false)` starts the existing smooth facing handoff. Pass
`true` only when an immediate turn is required. `StopMovement()` cancels the route;
it is not a pulse maintenance call.
