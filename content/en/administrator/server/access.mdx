# 🔑 Access

This documentation is public. It is not an access directory or a credential store.

## Request access from the service owner

Tell the maintainer which environment and task you need, such as viewing metrics
or investigating one failed route. Ask for the minimum access needed for that
task through an approved private channel.

The handoff should identify the correct service, account or role, authentication
method and expiry. If a private runbook or secret store has not been established,
agree on an approved destination before sharing operational details. Do not put
the handoff in a public issue, pull request, chat transcript or screenshot.

## Separate permissions

| Task | Access to request |
| --- | --- |
| Inspect metrics or logs | Read-only monitoring access where available. |
| Review a build or release | Access to the relevant repository and workflow results. |
| Deploy, restart or change a service | Explicit operator permission for that environment. |
| Approve world-data submissions | The World API review role authorized by its owner. |
| Manage credentials or network rules | Explicit permission for the affected account or infrastructure. |

Repository access does not automatically grant production access. A public app
endpoint also does not grant permission to use an administrative endpoint.

## Connect using the approved instructions

Use the current private access instructions supplied by the owner. Obtain
credentials directly from the approved store; avoid copying them into commands
that may be retained in shell history or build logs.

For a support report, include the operation, time, service revision and sanitized
error. Leave out passwords, tokens, key files, account identifiers and private
host details. The maintainer can request additional evidence privately.

## Lost, expired or exposed access

Ask the owner to revoke or renew the affected access. Do not try credentials
found in an older page or Git revision. Removing published text does not make an
exposed credential safe to reuse.

See [Operations](/en/administrator/server/operations) for the rotation handoff and
[Monitoring](/en/administrator/server/monitoring) for incident evidence.
