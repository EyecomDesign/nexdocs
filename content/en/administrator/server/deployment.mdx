# 🚀 Deployment

Use the release workflow in the service's current repository and the operator's
approved private runbook. This page describes the review and verification steps;
it does not authorize a production deployment.

## Before a release

1. Identify the repository, target environment, source revision and intended
   change. Check that the build artifact corresponds to that revision.
2. Review the change, automated checks and any data or configuration migration.
   Confirm compatibility with the clients and datasets that will use it.
3. Identify the previous working release and the rollback procedure before making
   a change.
4. Have an authorized operator obtain runtime credentials from the approved
   private store. Pass them through the deployment platform's secret mechanism.
5. Record the release revision and the verification plan without publishing
   credentials, internal addresses or environment inventory.

## Verify the deployed service

Check the actual deployed revision and the service's documented health check.
Then exercise a small representative operation, such as a route request for a
known supported map. Confirm the response and inspect relevant error, latency
and resource metrics.

A successful build does not establish that the service is reachable or that the
correct dataset is available. Keep the pre-release and post-release observations
separate so a later investigation can identify what changed.

## Rollback

If verification fails, use the approved rollback procedure for that service.
Confirm the previous artifact is compatible with any data changes before restoring
it. Recheck health and the representative operation after rollback.

Record the affected revision, time, symptom and sanitized outcome in the tracking
issue. Do not paste an environment file or a credential-bearing command as
evidence.

## Documentation-site deployment

The documentation site has its own build and deployment workflow. Its source of
truth is the [NexDocs repository](https://github.com/EyecomDesign/nexdocs).
Navigation-service deployment and documentation deployment are separate changes.

After a documentation deployment, check real public pages and search output in
addition to the build result. The
[monitoring checklist](/en/administrator/server/monitoring) explains how to report
a failed runtime check.
