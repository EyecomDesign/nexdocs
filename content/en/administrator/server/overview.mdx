# 🌍 Server Overview

Nexor uses navigation services to turn a destination into a walking route. This
section explains the service responsibilities and the checks used when operating
them. Deployment addresses, administrator accounts and credentials belong in the
operator's approved private records.

## Service responsibilities

| Part | Responsibility |
| --- | --- |
| Bot client | Sends a route request for the current game flavor and map, then follows an accepted route. |
| Navigation API | Accepts requests and returns route results or a failure that the caller can handle. |
| Path workers and datasets | Calculate routes against the appropriate map data. |
| Monitoring | Helps authorized operators distinguish request failures, capacity problems and missing data. |

The World API has a different job: it provides world records such as service NPCs
and navigation connections. A working world-data lookup does not by itself prove
that a walking route can be calculated. See the
[World API overview](/en/administrator/world-api/overview) for that data workflow.

## Check the correct environment

Before diagnosing an incident, identify the bot revision, client flavor, map,
time and affected operation. Then ask an authorized operator to confirm the
active service revision and dataset. Use the current deployment record rather
than assuming that a host, container image or capacity value from an older guide
is still in use.

## Public and private information

Public documentation can explain interfaces, expected behavior and troubleshooting
steps. Operational credentials, origin addresses, privileged access instructions,
firewall inventories and current infrastructure identifiers require a private
handoff from the service owner. Removing a value from this site does not revoke it
or erase earlier copies.
