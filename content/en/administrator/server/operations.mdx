# 🛠️ Operations

An authorized operator carries out maintenance using the current private runbook.
The public documentation describes the purpose and verification of each task;
it does not contain production access details.

## Rotate an exposed credential

1. Identify the credential and affected service privately. Confirm who is
   authorized to change it.
2. Assess where the value may have appeared, including Git history, old
   deployments, search artifacts, caches and downloaded files.
3. Generate the replacement in the approved credential system and update its
   authorized consumers through their secret mechanism.
4. Verify intended access still works, then revoke or invalidate the previous
   credential according to the service's supported procedure.
5. Check relevant access evidence and record the result privately.
6. Record only a sanitized completion statement and any remaining work in the
   public tracking issue.

Current values stay in the approved private store. Source cleanup is only one
part of remediation; it does not revoke credentials or remove earlier copies.
History rewriting, cache purges and production changes require explicit operator
authorization.

## Refresh map data or enable a flavor

Confirm the source, client flavor and map-data format before transferring or
activating a dataset. Follow the current private procedure for staging, integrity
checks, storage capacity and activation.

After activation, test a known request for the intended flavor and map. Keep
dataset validation separate from proving an entire in-game journey. Do not
assume a directory or exported file establishes complete route coverage.

## Inspect logs or restart a service

Use read-only diagnostics first. Record the affected time window and service
revision, then inspect the relevant logs without exporting credentials or
unrelated customer information.

Before a restart, identify active work, the expected interruption and the recovery
check. Afterward, verify health and a representative request. Use the
[Deployment](/en/administrator/server/deployment) procedure when the change also
replaces an artifact or configuration.

## Network and capacity maintenance

An authorized operator should verify current provider guidance and the active
network configuration before changing access rules. Keep origin addresses,
firewall inventories, account identifiers and privileged commands in the private
runbook.

Review resource usage and storage headroom through
[Monitoring](/en/administrator/server/monitoring). Record the reason for a change
and its sanitized verification result; obtain service access through
[Access](/en/administrator/server/access).
